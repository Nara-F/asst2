# 作业 2：从零构建任务执行库

**截止时间：10 月 16 日（星期四）晚 11:59；总分 100 分。**

## 概述

本作业要求从零实现一个支持并行任务执行的 C++ 任务系统。你将学习使用线程池管理任务、使用互斥锁和条件变量协调工作线程、根据任务图依赖调度任务，以及根据工作负载特征进行高效调度。

## 环境配置

评分和性能测试将在 AWS `c7g.4xlarge` 实例上进行。请按照 [云端配置说明](cloud_readme.md) 设置虚拟机，并确保代码能在该环境中运行。**不要修改提供的 `Makefile`，否则可能破坏评分脚本。**

## A 部分：同步批量任务启动

需要实现 `TaskSystemParallelSpawn`、`TaskSystemParallelThreadPoolSpinning` 和 `TaskSystemParallelThreadPoolSleeping`。首先运行测试熟悉 `TaskSystem` 接口与工作负载。

### 第 1 步：并行任务系统

`TaskSystem` 构造函数的 `num_threads` 是实现最多可以使用的工作线程数。最简单的正确方案是在每次 `run()` 开始时创建线程，在返回前由主线程 join；但频繁创建线程会产生较大开销。请思考静态或动态任务分配，以及哪些共享状态需要保护。

### 第 2 步：线程池

设计持续运行的工作线程，让它们不断检查是否有任务可执行（spinning）。需要考虑工作线程如何发现新工作，以及 `run()` 如何判断一次批量启动中的所有任务都已完成。

### 第 3 步：无任务时休眠

没有工作时，工作线程不应占用 CPU。可以使用条件变量让线程休眠，并在有新工作时唤醒；调用 `run()` 的主线程也可以在等待任务完成时休眠。此部分容易出现竞态条件，请考虑各种线程交错情况并自行增加测试。评分还会使用起始代码未提供的工作负载测试正确性。

## B 部分：支持任务图

实现异步任务启动和显式依赖。`runAsyncWithDeps()` 应立即返回；任务只有在依赖的批量启动全部完成后才变为可执行状态。建议维护两个结构：等待依赖完成的任务，以及无需等待、可放入 ready queue 的任务。

可以假设程序只使用 `run()`，或只使用 `runAsyncWithDeps()`；不必处理混合情形。`run()` 可以通过 `runAsyncWithDeps()` 和 `sync()` 实现。也可以假设除实现创建的线程外没有额外并发调用者。
